# Debt Fixes - Input Tool and Version Gate

<product-contract>

## Product Requirements

- Problem and users:
  - The model-visible `user_input` tool advertises a `question` parameter that the implementation silently discards, so a model can compose a question the operator never sees. Prompt authors and their models need the advertised tool contract to match behavior.
  - The executor's version gate admits `promptforge: 1` documents under a temporary dual-read transition, but only version-0 semantics exist; those documents fail mid-run with confusing errors instead of a clean rejection. Authors need incompatible documents rejected at the gate.
- Goals:
  - The input tool's advertised schema and description state only what the tool does.
  - The version gate accepts `promptforge: 0` only.
  - Every existing prompt document and inline test string declares `promptforge: 0`.
- Non-goals:
  - Do not extend `InputBroker` with a question channel; that is a real feature for a later host-interaction pass.
  - Do not fix DEBT-UPM-01 (raw-id fallback context window); the operator accepts it as pre-product debt.
  - Do not build an interim history restore for DEBT-UPM-03; the planned database-driven system will own agent memory.
  - Do not edit historical records under `vibe/`; dated design documents and the ledger keep their historical `promptforge: 1` mentions.
- Success criteria:
  - A `promptforge: 1` document is rejected at run start with the typed unsupported-version error.
  - The input tool's advertised schema carries no `question` property and its description makes no ask-a-question promise.
  - No `promptforge: 1` string remains outside `vibe/`.
  - All affected crate suites, clippy with `-D warnings`, and `cargo fmt --all --check` pass.
- Constraints:
  - `promptforge: 0` is the target; never propose incrementing it.
  - Land as two commits, one per debt.
- Open questions:
  - None.

## Functional Specification

- Actors and workflows:
  - A model in a brokered `models.loop` scope sees the `user_input` tool and may call it; the tool waits for operator input and returns it.
  - An author or test runs a prompt document; the executor checks the frontmatter version before any section runs.
- Inputs and outputs:
  - The input tool advertises an empty properties object and the description "Give the user the opportunity to add a prompt and wait for their typed input."
  - The version gate accepts exactly `promptforge: 0`.
- States and validation:
  - Version validation happens once at run start, before section execution.
- Errors and recovery:
  - A `promptforge: 1` or other non-zero document fails with the existing typed `UnsupportedVersion` error naming the declared version.
  - A document with no version fails with the existing structure parse error.
- Security and privacy behavior:
  - No change.
- Acceptance criteria:
  - A behavior test rejects a `promptforge: 1` document at the gate.
  - A schema test asserts the input tool advertises no `question` property.
  - Migrated inline test suites pass unchanged in every other respect.

</product-contract>

<implementation-contract>

## Technical Design

- Architecture:
  - No architectural change. The input tool's wire contract narrows to its existing behavior; the version gate narrows to the only implemented semantics.
- Modules and interfaces:
  - `crates/promptforge-core/src/input.rs`: `InputTool::description` becomes "Give the user the opportunity to add a prompt and wait for their typed input."; `parameters_schema` drops the `question` property, leaving an empty properties object; the `call` doc comment no longer mentions a question channel.
  - `crates/promptforge-core/src/execute.rs`: the gate arm `Some(SUPPORTED_MAJOR | 0) => {}` becomes `Some(0) => {}` and the dual-read comment is deleted.
  - `crates/promptforge-core/src/execute/support.rs`: `SUPPORTED_MAJOR` is removed when no use remains, or repurposed to name the zero gate.
  - `crates/promptforge-parser`: confirm the parser's own version handling agrees with the 0-only gate.
- File and public API changes:
  - Migrate every `promptforge: 1` occurrence to `promptforge: 0`: `crates/promptforge-core/src/execute/tests/` (`scheduler.rs` 91, `model_and_reply.rs` 24, `exit_rules.rs` 9, `debug_and_counts.rs` 8, `live_infer.rs` 14, `observations.rs` 4, `mod.rs` 4, `input.rs` 1, `models_loop.rs` 1, `local_tools.rs` 2, `lazy_prose.rs` 1, `exec_flow.rs` 1), `crates/promptforge-core/src/execute/context.rs` (1), `crates/promptforge-core/src/observe.rs` (1), `crates/promptforge-parser/src/tests.rs` (7).
  - Tests that assert a `promptforge: 1` document is accepted are inverted to assert typed rejection.
- Data, persistence, failure, security, and privacy constraints:
  - The gate flip changes which persisted prompt documents are accepted; that is the point of the fix and is operator-resolved.

</implementation-contract>

  - Existing version-rejection tests (`promptforge: 2` and unknown versions) keep passing.
- Integration and end-to-end:

  - `cargo test -p promptforge-lua` and the workshop-server suite confirm no consumer depended on the old schema or gate.
- Regression, security, and performance:
  - No performance-sensitive paths touched.
- Exit criteria:

<decision-record>

## Decision Record

- Decisions:
  - Narrow the input tool's advertised contract to its behavior rather than plumbing the question through. The operator decided: "The model never calls that, only the Lua. The tool should be described as 'Give the user the opportunity to add a prompt' or something (figure it out)."
  - Flip the version gate to `promptforge: 0` only and migrate every prompt, including inline test scaffolding. The operator decided: "yes flip the fate to 0, fix every existing prompt that you can find" (read "fate" as "gate").
  - Accept DEBT-UPM-01 (raw-id fallback context window) without a fix. The operator decided: "its not a big deal. no one is really using this yet, we are still building it."
  - Give DEBT-UPM-03 (relaunch amnesia) no interim fix. The operator decided: "we are going to build a very robust database-driven system and when we do that, then we will save the agent memory."
  - Land the two fixes as two commits, one per debt.
- Rejected alternatives:
  - Reject extending `InputBroker::user_input` with a question parameter because it is a public trait change for a feature no current consumer uses; revisit when a host-interaction pass designs the question channel.
  - Reject the interim host-seeded history rebuild for DEBT-UPM-03 because the database-driven persistence system will own agent memory; revisit only if that system is cancelled.
  - Reject migrating historical `vibe/` documents because dated design records must keep their historical contents; revisit never.
- Assumptions, risks, and notes:
  - Any un-migrated `promptforge: 1` document in the wild now fails at the gate instead of mid-run; that is the intended behavior change.
  - The parser crate has its own version handling; the migration keeps it consistent with the 0-only gate.

</decision-record>
