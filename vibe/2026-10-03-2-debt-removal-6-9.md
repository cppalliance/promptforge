## Technical Design

- D1-1: docs only.
  - Rewrite `crates/promptforge-internal/types/src/cancel.rs:11-13` to say a Host stops a run through `harness::RunControl::cancel`, which sets this flag, and drop the `harness-runner` and tokio-token wording. `promptforge-types` cannot link to `harness` (dependency direction), so the name stays in backticks, not an intra-doc link.
  - Delete the `- item: promptforge::model::StreamDelta` line at `tools/cicerone/plans/promptforge.md:259`. Its existing detector, `tools/cicerone/scripts/survey.py` ("stale {key}: not in the public API", around `:160`), is the verification.
- D1-2: private-crate shape change in `harness-runner`.
  - Remove `seed`, `started_at`, and `parse_events` from `Prepared`, and `events` from `PrepareError::Parse`, `::Refused`, `::Input`. Simplify `PrepareError::ended` and every constructor accordingly.
  - Rewrite the module doc, the `prepare` doc, and the `Prepared.run_id` doc to name `Harness::run_to_end` and the recorder as the place a caller reads the run's events.
  - Keep `#[expect(clippy::result_large_err)]` with a corrected reason if the lint still fires after the fields go (the variants still hold `ParseError`, `RunError`, `InputFileError`); remove it if clippy reports the expectation unfulfilled.
- D1-3: delete `WaitRegistry::resend_unresolved`, its doctest, and `reconnect_resends_unresolved_waits_in_creation_order` in `crates/workshop/agents/src/input-tests.rs`. Rewrite the two doc passages to say the registry retains unresolved waits and the agent socket re-announces them from `Conversation::unresolved_waits()` on reconnect and after lag.
- D1-34: add a runtime paragraph to the `GatewayBroker` type doc and a sentence to the `harness-gateway-client` README: the broker's futures, including `models()`, need a tokio runtime (reactor and timer), so a Host that uses it awaits `Harness::run` inside one; the Harness itself needs none.
- D1-29: in `layout::is_stale`, when `layout` exists with no row, return not stale if `runs` has no rows; keep stale when `runs` has rows or `layout` is missing. Add a query constant in `crates/workshop/run-log/src/schema.rs` (for example `SELECT 1 FROM runs LIMIT 1`). `stamp` then inserts the version. Two processes may both insert; duplicate rows of the same version are harmless because `stamped` reads the first row. Update the `is_stale` doc.

  - D1-2 removes `seed` and `started_at` along with the event copies, because the tests that read them can read the recorded `RunMeta` instead. Rejected: keeping them for the deferred "split preparation from the run" work, because that reserves a future Host-facing API, not fields of a private crate.
  - D1-3 deletes the registry method instead of wiring the socket through it; the socket's resend over `unresolved_waits()` is the tested path.
  - D1-29 treats an unstamped, empty log as fresh rather than wrapping creation and stamping in one transaction, because Turso 0.7.2's transaction support for DDL batches is unverified and the empty-runs rule needs no new SQL feature.
- User-resolved choices:
  - The operator chose the target `1f0554a2..HEAD` (everything since the previous collection) over the whole PR or the harness-per-run plan alone.
  - The operator added D1-34 and D1-29, which both passes had rejected as weak, as cheap fixes.
  - No hard-to-reverse remediation arose, so no architecture choice was raised.
- Assumptions and risks:
  - D1-29 residual: a file left unstamped by an interrupted open of a different build, with an empty `runs` table in another column layout, would be stamped with this build's version. That needs a downgrade plus an interrupted first open; accepted.
  - D1-2: whether `clippy::result_large_err` still fires after the fields go is unknown until clippy runs; the Technical Design covers both outcomes.
  - Analysis limits: nothing was executed during analysis. `47c9caa88` (Engine round numbering internals) and the docs-only commits `7a426ff67`, `671a215ac`, `0f3d5c50b` were covered by search rather than a full read.
