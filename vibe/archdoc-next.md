# PromptForge architecture queue

- N1. Keep every required verification gate green before advancing or checkpointing a component.
- N2. Make each implementation change one bounded behavior slice and resolve every review finding before beginning the next slice.
- N3. Separate portable, platform-native, hardware-backed, and packaging verification into explicit owning lanes.
- N4. Prove release workflow event, permission, artifact, and nonpublishing paths on a fork before relying on upstream scheduling.
- N5. Release Gateway, Workshop, libraries, and native accelerator artifacts independently on their appropriate platforms.
- N6. Require signed platform artifacts and a signed manifest before any desktop update is installed or relaunched.
- N7. Move evergreen download aliases only by repointing them to immutable versioned artifacts.
- N8. Concentrate provider response quirks and dialect translation at one protocol normalization boundary.
- N9. Distinguish failures before connection from mid-flight failures that may already have reached or billed a provider.
- N10. Treat missing or ambiguous protocol dialect selection as visible admission failure rather than guessing.
- N11. Limit resource concurrency at device or lane boundaries and expose backpressure rather than hiding saturation.
- N12. Let the gateway queue own model-work backpressure unless measured non-model work requires a separate host cap.
- N13. Add continuous background watchdogs only when measured failures justify their lifetime and coherency costs.
- N14. Keep capability constraints separate from per-invocation sampling and generation settings.
- N15. Bind prompt-local model aliases once per run from validated gateway catalog metadata.
- N16. Freeze capability bindings after their declaration phase so later execution sees read-only self-contained bindings.
- N17. Install section-lifetime host APIs once so all chunks and handlers share one coherent environment.
- N18. Replay frozen declarations without resolving external capabilities again.
- N19. Move state across sections through the store or named typed payloads, never shared Lua memory.
- N20. Permit raw store reads only for trusted code and wrap every model-facing reinjection as untrusted content.
- N21. Exclude HTTP error bodies from model-facing recovery results.
- N22. Validate, sanitize, bound, filter, and diversify external results before exposing them to a model.
- N23. Add caches only after repeated workloads justify an explicit invalidation and coherency policy.
- N24. Associate ignored secret sidecars with configuration layers by identity instead of adding secret syntax to configuration.
- N25. Remove declarative fields that execution does not honor rather than retaining inert compatibility configuration.
- N26. Normalize fan-out input at the Lua boundary before execution.
- N27. Reuse parsed section items instead of reparsing Markdown in author or executor code.
- N28. Keep control graphs level-local so an address sees only siblings and direct children unless explicit transfer occurs.
- N29. Keep arm-specific identity, cancellation, observation, exhaustion, and outcome mapping in a thin adapter.
- N30. Make direct inference one fresh tool-free turn that cannot mutate reply or system state.
- N31. Reject tool and model aliases that collide with declarations or earlier local registrations.
- N32. Return categorized errors for malformed syntax and offsets instead of allowing parser input to reach panic paths.
- N33. Let a missing or malformed optional environment sidecar degrade softly when all required values resolve elsewhere.
- N34. Keep public source line bounds one-based, inclusive, and clamped so citations preserve source coordinates.
- N35. Report a missing declared output distinctly without retroactively failing an otherwise completed run.
- N36. Keep execution independent of whether the run-scoped store uses memory or files.
- N37. Express resume and skip behavior through ordinary prompt-owned store operations rather than executor special cases.
- N38. Represent background work with claim-once completion handles and one bounded wait-any primitive.
- N39. Declare an inference child ready only after a representative warm-up succeeds; any pre-probe exit is failure.
- N40. Preserve upstream request IDs and structured status, and never blindly retry work that may already have completed or been billed.
