# Model Taxonomy and Cloud Models UI

<product-contract>

## Product Requirements

The `shared-cloud-providers` crate now covers the full surveyed provider set - 23 providers across Prime, Subprime, and Aggregator tiers - with keyless descriptors, concurrent fetches, and a profile-dir secrets loader, and the aggregation workflow in `cppalliance/promptforge-cloud-providers` publishes the sheet weekly as a rolling `models` release holding `cloud-provider-models.json`. What the sheet lacks is the taxonomy a UI needs to be browsable, and what the gateway and config UI lack is any consumption path for it. This plan adds both: taxonomy computed inside the provider files because that is what the crate is for, and a Cloud tab that explores the sheet and adds models, with keys handled where they already live - on the Secrets tab.

- Problem and users: the sheet's entries are flat (OpenAI lists 124 models with no grouping; Deepgram lists 547 rows that are really 143 models repeated per language; OpenAI's whisper, tts, embedding, image, and video models all read as `chat`); the gateway has no way to fetch or serve the sheet; and operators add remote models by hand-writing `[[model]]` entries in `gateway.toml` (`crates/gateway-config/src/config.rs`, `ModelConfig`) while a normalized catalog sits unreachable. Users are gateway operators picking models in the config UI, and the operator running the binary locally to verify the sheet.
- Goals:
  - Model taxonomy baked into all 23 provider files: each entry names its `family`, dated snapshots and SKU variants point at their canonical alias via `variant_of`, and per-language duplicates collapse into one entry with `languages`. The sheet schema gains these fields outright - no version bump, no compatibility path: the operator's words - "This is not schema-v2. Just overwrite. Delete the currently published release." (2026-09-14). The operator's crate thesis: "each provider file like anthropic.rs needs to have what you said baked in ... The whole point of that crate is to do this work."
  - Each provider's OpenAI-compatible chat base URL (when it has one) and environment variables (with roles and defaults) published in its sheet slice, so the UI needs no hardcoded provider knowledge and never mistakes a model-list URL for a chat endpoint.
  - `kind` inferred from model names for the IDs-only dialect providers, so `whisper-1`, `tts-1`, `text-embedding-3-small`, `gpt-image-1`, and `sora-2` stop reading as `chat`.
  - The gateway downloads the sheet from the release asset URL, caches it on disk in the profile directory, and on launch checks once whether the cache is older than a week and refreshes it in the background - the operator's words: "the gateway needs to download and cache the json asset file. and on launch check it once per week to see if there's a newer one." It serves the cached sheet to the config UI on a loopback-walled admin route - the UI's only data source for the Cloud tab and the Secrets dropdown - so the browser never talks to GitHub, the disk cache serves every session, and the UI works offline against last week's sheet. This is an admin-side detail for the config UI, not product API: hosts still get configured models through `GET /v1/models`.
  - A new "Cloud" top-level tab in the config UI laid out top to bottom as the operator specified: kind lozenges as an exclusive radio group (chat, image, video, STT, TTS); a provider dropdown grouped by tier (Prime alphabetical, separator, Subprime alphabetical, separator, Niche, separator, Aggregator); a family dropdown scoped to the selected kind and provider; and a full-height table with no scrollbar of every model matching kind, provider, and family.
  - An add-model flow writes a `[[model]]` entry - plus a `[[endpoint]]` when the provider has none - through the existing shadow/apply config path, with a confirm-details step when the sheet lacks required fields.
  - The Secrets tab's add-variable row gains a provider dropdown: picking a provider fills in its variable name(s) so the operator never types `ANTHROPIC_API_KEY` from memory - the operator's words: "Maybe the Secrets page can have a dropdown for providers?" (2026-09-14). Free-text entry stays for non-provider variables.
- Non-goals: provider coverage, keyless descriptors, concurrent fetching, and the secrets loader (all in the tree); changes to the aggregation workflow (in place, in the separate repo); Niche static lists; SiliconFlow; live per-provider fetches from the gateway; key entry, storage, or validation in the Cloud tab (keys stay on the Secrets tab); workshop UI changes; native (non-OpenAI-shaped) protocols for Bedrock or the media providers; automatic profile membership; embedding and classifier models (hidden from the view by the operator's five-kind choice); gateway event-loop or startup rework (none is needed - see Decision Record).
- Success criteria: every entry in the emitted sheet has a non-empty `family`; dated snapshots whose alias exists in the same provider list point at it via `variant_of`; Deepgram emits one entry per distinct model id with its languages collected (143 entries, not 547, against the 2026-09-14 sheet); OpenAI's non-chat models report their real `kind`; every provider slice publishes `env_vars` and, where the provider has one, `openai_base_url`; the rebuilt release parses with the new shape; the gateway boots with no network and serves the cached sheet; a launch with a week-old cache refreshes it in the background without blocking boot; the UI cascade never produces a dead end the operator cannot see coming; adding a model produces a config that validates, applies, and shows the model in the running catalog; the Secrets dropdown fills variable names from the sheet.
- Constraints:
  - The real secrets file at `~/.promptforge/cloud-provider-secrets.env` must never be read, printed, copied, or committed by any person, agent, or tool. The binary loads it; tests use fixture files inside temp-dir homes only; nothing else touches it. This is an absolute operator directive (2026-09-14).
  - Endpoint facts come from the 2026-09-14 provider-landscape survey recorded in `vibe/2026-09-14-2-provider-model-sheets.md`, whose underlying evidence set is the 2026-09-14 research collection in the workspace's research staging area (`cabinet/_research/`, filenames prefixed `2026-09-14-`). The official docs govern on any conflict.
  - Naming conventions observed in the published 2026-09-14 sheet, which the taxonomy rules must handle: OpenAI groups by minor version prefix (`gpt-5.4` covers `gpt-5.4`, `gpt-5.4-pro`, `gpt-5.4-mini`, `gpt-5.4-nano`) with dated snapshots `-YYYY-MM-DD` and `-MMDD`; Gemini by version prefix (`gemini-3.5`, `gemini-3.1`, `gemini-2.5`) plus product lines (`gemma`, `veo`, `lyria`, `deep-research`, embeddings) with snapshots `-MM-YYYY`; Anthropic by line (`opus`, `sonnet`, `haiku`, `fable`) with snapshots `-YYYYMMDD`; xAI by `grok-<version>` with `-MMDD`; Mistral by product line (`mistral-medium`, `codestral`, `ministral`, `voxtral`, `magistral`, `ocr`, `embed`) with `-YYMM` snapshots; Cohere by line (`command-a`, `command-r`, `aya`) with `-MM-YYYY`; Qwen (DashScope) by version prefix (`qwen3.8`, `qwen3.7`, `qwen3.5`, `qwen3`) plus resold vendors (`deepseek`, `kimi`, `glm`, `wan`) and product lines (`qwen-image`, `qwen3-tts`, `qwen3-asr`, `qwen-mt`) with `-YYYY-MM-DD`, `-MMDD`, and `-YYMM` snapshots; OpenRouter and NVIDIA by the `vendor/` slash prefix, OpenRouter additionally with `:free` and `:batch` SKU suffixes; Deepgram by model line (`nova-3`, `nova-2`, `enhanced`, `general`, `phoneme`) with one row per language. Snapshot suffixes are ambiguous across vendors (`-2508` is YYMM for Mistral but could be MMDD elsewhere), so each provider file picks its own patterns. Families for the Subprime providers not in the 2026-09-14 sheet (the operator had not provisioned their keys) follow the same per-vendor reasoning against their documented catalogs.
  - Tiers are a curated product opinion with a functional basis (settled in `vibe/2026-09-14-2-provider-model-sheets.md`): Prime and Subprime have working key-callable model-list endpoints, Niche have none (their slices are static compiled-in lists), Aggregators list many providers' models through one endpoint. The registry and its tier assignments are in `crates/shared-cloud-providers/src/lib.rs`.
  - The binary contract from `crates/shared-cloud-providers/src/main.rs` stands: keys via each descriptor's `key_env` (`Option`; `None` for keyless providers), the profile-dir secrets file loaded with override semantics, previous-sheet URL via `MODELS_SHEET_PREVIOUS_URL` (optional), output to argv[1] (default `./models.json`), exit code signals success or failure, HTTP 404 on the previous-sheet URL means first run. The 404-versus-fatal split is deliberate - it is the DEBT-PMS-1 repair (commit `5945b706`): a configured-but-unreachable or unparseable previous sheet must never silently publish a regressed one.
  - The published `models` release has already been deleted (operator, 2026-09-14), so the old-shape sheet no longer exists at the stable URL. Stage 1 closes by pushing the crate changes and dispatching the workflow to rebuild the release; that rebuilt release is stage 1's deliverable and the gateway and UI stages build against it. Why the deletion mattered: the new binary parses the previous sheet with the new required fields, so an old-shape release would fail to parse - and a parse failure is not a 404, so under the DEBT-PMS-1 rule the run would be fatal rather than a first run. With no release, the previous-sheet URL 404s, the run proceeds as a first run (every provider fetched fresh with the workflow's keys), and the fresh sheet publishes. Risk: the workflow's weekly cron (Monday 12:00 UTC) could fire with the old binary before stage 1 lands and republish an old-shape sheet; if it does, delete the release again (`gh release delete models --cleanup-tag`) immediately before the dispatch. The rebuild is a manual dispatch of the workflow in `cppalliance/promptforge-cloud-providers` (the plan for that workflow is `vibe/2026-09-14-5-models-aggregation-workflow.md`), which clones `cppalliance/promptforge` master.
  - Admin routes are loopback-walled (`crates/gateway/src/lib.rs` 539-561, 584-594); the new route follows the same wall. Config writes are full-document shadow writes: `PUT /admin/config` stages, `POST /admin/config-apply` promotes (`crates/gateway/src/config_write.rs`, `crates/gateway/src/config_apply.rs`); there is no per-item append route. `ModelConfig.context` is a required `u32` while the sheet's `context_window` is `Option<u32>` - the nullability gap is deliberate. The gateway's `Protocol` enum supports only the OpenAI wire shape for remote endpoints (`crates/gateway-config/src/config.rs` 131-132, 500-503); a provider is addable exactly when it exposes an OpenAI-compatible chat API, which the sheet records per provider as `openai_base_url`. Anthropic qualifies: its compatibility endpoint `https://api.anthropic.com/v1` is already what the gateway's configs and tests use (`crates/gateway-config/src/config/tests.rs`). The descriptor's `base_url` is the model-list endpoint's base and is a different URL for most providers; it is never written into an `[[endpoint]]`. Dependency rules allow `gateway` to depend on `shared-*` crates (`vibe/archdoc.md`; `build-xtask/src/product.rs`; existing deps `shared-loopback`, `shared-sidecar`, `shared-progress`).
  - The sheet URL defaults to `https://github.com/cppalliance/promptforge-cloud-providers/releases/download/models/cloud-provider-models.json`.
  - The kind lozenges map to `ModelKind` as chat to `chat`, image to `image`, video to `video`, STT to `transcription`, TTS to `speech`; `embedding` and `classifier` entries are excluded from the view.
  - Workspace conventions apply: edition 2024, workspace lints, no file over 500 lines (enforced by `build-xtask`), tests beside the change; no secret material in the crate.

## Functional Specification

One actor in two seats: the operator verifying the sheet with a local binary run, and the operator in the config UI. Between them sits the gateway as the sheet's cache and the UI's data source: it never blocks startup on the sheet, serves what it has, and refreshes in the background.

- Actors and workflows:
  - Sheet build (binary, local or in the workflow): every provider file normalizes its list - assigning `family`, collapsing snapshots and SKU variants under their alias, merging per-language duplicates, inferring `kind` from names where the endpoint reports none - and each slice publishes the descriptor's `openai_base_url` and `env_vars`; the binary propagates last-known-good data for failures when history exists and writes the merged sheet.
  - Gateway sheet lifecycle: at launch the gateway loads the cached sheet from `<profile>/cloud-provider-models.json` if present (a local file read, never network), compares its `generated_at` to now, and when the cache is missing, unparseable, or older than one week spawns a background task that downloads the sheet and atomically replaces the cache file; a launch with a fresh cache does no network work for the sheet at all. The admin route serves the in-memory copy; a refresh action forces a background re-download regardless of age.
  - UI: the operator opens the Cloud tab; picks a kind, then a provider, then optionally a family; the table shows the matching canonical models; the operator clicks add on a row, confirms details, and applies the config change. On the Secrets tab, the operator picks a provider from the dropdown to fill in variable names, pastes values, saves, and applies.
- Inputs and outputs: provider list-endpoint JSON into the binary; one sheet file out. The release URL into the gateway's background downloader; the cached sheet JSON out of `GET /admin/cloud-models`; staged config JSON and apply results out of the existing admin routes.
- States and validation:
  - Sheet: `variant_of` is set only when the alias id exists in the same provider's list; a dated id with no alias is canonical; a variant always has the same `family` as its canonical, so the cascade's family filter never separates them. `family` is required - the compiler enforces it, because the field has no serde default. Keyless providers publish an empty `env_vars`; every slice, including `unavailable` ones built with no history, publishes `openai_base_url` and `env_vars` from the descriptor.
  - Gateway: the sheet state is one of absent (no cache yet; the route answers with a loading indication), fresh cache (served as-is), stale cache (served while a background refresh runs), or unreachable (no cache and the download failed; the route answers with the error). A cache file that fails to parse - one left by an earlier build with a different shape - is treated as absent: logged, ignored, and overwritten by the next successful download. A download already in flight is never duplicated; route requests during it get the stale cache or the loading state.
  - UI: loading, loaded (showing `generated_at`), and unreachable (error with retry), driven by the client-side sheet store; a view open when the sheet lands re-renders in place. Names: the table shows each entry's `display_name` as primary text with the `id` beneath when the two differ; providers reporting no display name show the id alone. Cascade behavior: the kind radio defaults to chat; the provider dropdown lists every provider in the sheet grouped by tier, with providers that have no models of the selected kind (including the stale zero-model providers) rendered greyed and unselectable so menu positions stay stable across kind changes; empty tier groups are omitted (Niche has no providers today); the family dropdown defaults to "All families" and lists the distinct `family` values among the provider's models of the selected kind; the table lists canonical entries (those with no `variant_of`) matching the cascade, each with a "+N snapshots" disclosure that expands its variants beneath it when N is nonzero.
  - Add dialog: pre-fills from the sheet entry and requires operator input when `context_window` is absent (IDs-only providers); `name` defaults to the sheet `display_name` and stays editable; a variant row is addable too, since a pinned snapshot is a deliberate choice.
  - Secrets provider dropdown: the existing add-variable row (`NAME`, `value`, `Add Variable`) gains a tier-grouped provider `<select>` beside the free-text `NAME` field, populated from the sheet's provider slices. Choosing a provider fills the name field with its key variable and, for multi-variable providers, appends the sibling rows in one action - Bedrock adds `AWS_ACCESS_KEY_ID`, `AWS_SECRET_ACCESS_KEY`, and `AWS_REGION` (prefilled `us-east-1`); Foundry adds `AZURE_FOUNDRY_API_KEY` and `AZURE_FOUNDRY_ENDPOINT`; Azure Speech adds `AZURE_SPEECH_KEY` and `AZURE_SPEECH_REGION`. Key values are left empty for the operator to paste; configuration values are prefilled where the sheet gives a default. Keyless providers (empty `env_vars`) are greyed - nothing to add. Providers whose key-role variables are all already present in `gateway.env` are greyed too. Every provider in the sheet appears regardless of slice status - an `unavailable` provider is exactly the one whose key needs adding. Saving and applying follow the tab's existing shadow flow unchanged.
- Errors and recovery: failed provider fetches record `stale` with history or `unavailable` without, and never fail the binary run; a failed previous-sheet download on a configured URL is fatal before any write (the DEBT-PMS-1 semantics). A failed sheet download at the gateway leaves the previous cache in place and the UI in its unreachable or stale state; the gateway stays up. Shadow-save validation errors surface in the add dialog verbatim; a failed apply reverts per the existing revert path.
- Security and privacy behavior: no secret reaches the sheet; `openai_base_url` and variable names are public facts. The admin route is loopback-walled like its siblings; new endpoints are written with `api_key = "${KEY_ENV}"` indirection (the `Secret` type redacts on serialize, `crates/gateway-config/src/config.rs` 72-116) and real key values enter `gateway.env` only through the Secrets tab, never the Cloud tab; keyless providers get endpoints with no `api_key`.
- Acceptance criteria: every provider file's taxonomy tests pass and the every-entry-has-a-family assertion holds over a full fixture build; the republished release parses; the gateway serves the cached sheet with no network and refreshes a week-old cache in the background without blocking boot; the kind radio, provider dropdown, and family dropdown cascade as specified with greyed providers and the "All families" default; the table shows only rows matching all three and collapses variants under their canonical alias; a view open when the sheet lands re-renders in place; the Secrets dropdown fills variable names and adds multi-variable sets from the sheet; adding a model for a provider with no endpoint creates both entries and the model appears in `GET /v1/models` after apply; adding a second model for the same provider reuses the endpoint; a model from an IDs-only provider cannot be added without a context value; rows for providers with no `openai_base_url` (Bedrock and the media providers) show a disabled add action with the reason.

## Technical Design

One schema extension, one taxonomy helper module, a taxonomy and env-vars pass over all 23 provider files, one gateway module with a disk cache and a background downloader, one admin route, and on the UI side one new tab view, a subscribable sheet store, a provider accessor over the sheet, two pure helpers (cascade and merge), and a dropdown added to the Secrets view. The gateway's startup and event loop need no changes: the download is one bounded request on the existing tokio runtime, spawned after boot, with failure contained to the feature.

- Architecture:
  - Schema extension in `crates/shared-gateway-api/src/lib.rs`: `ModelEntry` gains `family: String` (the UI's first grouping level; required, so the compiler forces every provider file to set it), `variant_of: Option<String>` (the canonical alias this entry is a dated snapshot or SKU variant of; set only when that alias exists in the same provider's list), `variant: Option<String>` (the stripped suffix, e.g. `2026-03-05`, `free`, `batch`, for the UI's expander label), and `languages: Vec<String>` (the provider's own language codes, passed through as reported, empty when unknown or not applicable). `ProviderSlice` gains `openai_base_url: Option<String>` (the base URL of the provider's OpenAI-compatible chat API - the value an `[[endpoint]]` needs - or `None` when the provider has no such API) and `env_vars: Vec<EnvVar>` where `EnvVar { name: String, role: EnvRole, default: Option<String> }` and `EnvRole` is `key` or `config` - copied from the descriptor at build time, extending the slice's existing principle that a consumer can render from the sheet alone. The descriptor's existing `base_url` is the model-list endpoint's base and stays private to the fetch; it is not what an endpoint needs and is not published. No serde defaults, no version bump, no reader compatibility: the schema simply changes; the published release was deleted and the workflow rebuilds it. `schema_version` stays 1 - the field exists for the day a deployed reader needs it, and there are no deployed readers today.
  - Descriptor extension in `crates/shared-cloud-providers/src/lib.rs`: `Provider` gains `openai_base_url: Option<&'static str>` and `env_vars: &'static [EnvVarSpec]`, where `EnvVarSpec { name: &'static str, role: EnvRole, default: Option<&'static str> }` is the const-friendly twin of the schema's `EnvVar` (the schema type holds `String`s and cannot sit in a `const` descriptor); slice construction converts. `key_env` (already `Option<&'static str>`) stays the single key-role entry the binary passes to `fetch_models`; the provider file reads any further entries privately, as Bedrock, Foundry, and Azure Speech already do. Bedrock declares `AWS_ACCESS_KEY_ID` (key), `AWS_SECRET_ACCESS_KEY` (key), `AWS_REGION` (config, default `us-east-1`); Foundry declares `AZURE_FOUNDRY_API_KEY` (key) and `AZURE_FOUNDRY_ENDPOINT` (config, no default); Azure Speech declares `AZURE_SPEECH_KEY` (key) and `AZURE_SPEECH_REGION` (config, no default); single-key providers declare one key entry; keyless providers declare none. Slice construction in `sheet.rs` copies `openai_base_url` and `env_vars` for every slice status.
  - OpenAI-compatible chat bases per provider, each verified against the provider's official docs by the file's author before it is written (the research collection is the starting point): Anthropic `https://api.anthropic.com/v1` (the compatibility endpoint the gateway's configs and tests already use); OpenAI `https://api.openai.com/v1`; Gemini `https://generativelanguage.googleapis.com/v1beta/openai`; xAI `https://api.x.ai/v1`; DeepSeek `https://api.deepseek.com/v1`; Qwen `https://dashscope-intl.aliyuncs.com/compatible-mode/v1`; Moonshot `https://api.moonshot.ai/v1`; Meta `https://api.meta.ai/v1`; Mistral `https://api.mistral.ai/v1`; Cohere `https://api.cohere.com/compatibility/v1`; Baidu `https://qianfan.baidubce.com/v2`; MiniMax `https://api.minimax.io/v1`; StepFun `https://api.stepfun.ai/v1`; Groq `https://api.groq.com/openai/v1`; NVIDIA `https://integrate.api.nvidia.com/v1`; OpenRouter `https://openrouter.ai/api/v1`. `None` for Bedrock (SigV4 and the Converse API, not OpenAI-shaped), Foundry (per-resource endpoint, not a fixed URL), Azure Speech, ElevenLabs, Deepgram, Soniox, and Leonardo (no OpenAI-compatible API). A model is addable from the Cloud tab exactly when its provider's slice has an `openai_base_url`.
  - Taxonomy primitives in a new `crates/shared-cloud-providers/src/taxonomy.rs`: suffix strippers for the observed snapshot styles (`-YYYY-MM-DD`, `-YYYYMMDD`, `-MMDD`, `-YYMM`, `-MM-YYYY`), a `vendor_prefix` splitter for `vendor/model` ids, a `sku_suffix` splitter for `:free`-style suffixes, and a post-pass `collapse_variants(entries, split)` that sets `variant_of`/`variant` only when the base id exists in the list and copies the canonical's `family` onto the variant. The primitives are vendor-agnostic; which ones apply, and the `family` rule itself, are private to each provider file - the same private-variance principle the crate is built on. No regex dependency; the patterns are fixed-width and hand-parsed.
  - Per-provider taxonomy rules, one `family_of(id)` and one snapshot-pattern choice per file, following the naming conventions recorded in the Constraints: OpenAI minor-version prefix (`gpt-5.4`, `gpt-4o`, `o-series` for `o1`/`o3`/`o4`, product lines for image/realtime/audio/tts/whisper/embedding/sora); Gemini version prefix plus product lines; Anthropic by line (opus/sonnet/haiku/fable); xAI `grok-<version>`; Mistral product line; Cohere line; Qwen version prefix with resold-vendor and product-line families; OpenRouter and NVIDIA vendor prefix with OpenRouter SKU suffixes; Deepgram model line; the remaining Subprime files by their documented catalogs.
  - Deepgram dedup in `deepgram.rs`: the wire model retains its language field; normalization groups rows by id, emits one `ModelEntry` per distinct id, and collects the languages into `languages`. Against the 2026-09-14 sheet this turns 547 rows into 143 entries. ElevenLabs, Soniox, and Azure Speech likewise populate `languages` from their per-model language lists instead of dropping them.
  - `kind` inference for dialect providers: `openai.rs` maps name patterns to kinds (`whisper`/`transcribe` to `transcription`; `tts`/`audio` to `speech`; `embedding` to `embedding`; `image`/`dall-e` to `image`; `sora` to `video`; `moderation` to `classifier`; everything else stays `chat`). The `openai_shape::base_entry` default stays `chat`; each dialect file layers its own rules. Qwen, Moonshot, and Mistral get the same treatment for their `tts`/`asr`/`image`/`embed`/`ocr` lines.
  - Gateway sheet cache: `crates/gateway/Cargo.toml` adds `shared-gateway-api` and `shared-cloud-providers` workspace dependencies. A new module `crates/gateway/src/cloud_models.rs` holds the in-memory `Option<Sheet>` plus a download-in-flight guard behind a lock. At launch, after the async boot completes, the module loads `<profile>/cloud-provider-models.json` from disk when present and parseable, and spawns a background download only when the cache is missing, unparseable, or its `generated_at` is older than one week (the envelope timestamp is the age source - it survives file copies and needs no sidecar metadata); the task fetches with `shared_cloud_providers::fetch_sheet` over a purpose-built bounded client from the existing `gateway-protocol/src/http_util.rs` factory, and on success writes the new sheet to a temp file and renames it over the cache (atomic replace) before swapping the in-memory copy. The URL is a constant default with a `PROMPTFORGE_MODELS_SHEET_URL` environment override, matching the repo's `PROMPTFORGE_*` env convention; no config-schema change. The weekly check is a launch-time timestamp comparison, not a timer loop: a gateway that runs for weeks re-checks at its next launch, which is the operator's stated semantics.

Registered beside the other admin routes in `crates/gateway/src/lib.rs` and loopback-walled the same way.

## Decision Record

- Decisions:
  - Model taxonomy lives in the provider files, not in a UI: the operator's words - "each provider file like anthropic.rs needs to have what you said baked in ... The whole point of that crate is to do this work" (2026-09-14). Vendor naming conventions are private variance; the provider file is the one place that knows them, and the result is deterministic and fixture-testable.
  - The sheet schema gains `family`, `variant_of`, `variant`, and `languages` on entries and `openai_base_url` and `env_vars` on slices, all required, with no version bump and no compatibility path: the operator's words - "This is not schema-v2. Just overwrite. Delete the currently published release." (2026-09-14). There are no deployed readers, so nothing needs protecting; the required `family` lets the compiler enforce the taxonomy pass over every provider file.
  - `family` is a flat string, one level: the UI groups by it and can roll up further itself. Granularity per vendor is the minor version for OpenAI and Gemini (`gpt-5.4`, `gemini-3.5`) and the product line for Anthropic, Mistral, Cohere, and Deepgram (`opus`, `codestral`, `command-a`, `nova-3`) - the split that yields the most useful group sizes against the 2026-09-14 sheet (Anthropic by generation would give one or two models per family).
  - `variant_of` points only at aliases that exist in the same provider list; otherwise the dated id is canonical. A pointer to a nonexistent alias would give the UI nothing to attach the variant to.
  - Deepgram collapses per-language rows into one entry with `languages`: the 2026-09-14 sheet shows 143 distinct ids across 547 byte-identical-modulo-language rows, so the rows are one model each, not 547 models.
  - Language codes pass through as reported; no BCP-47 normalization in v1. Normalizing would invent a cross-vendor scale, contrary to the normalize-the-knob-never-the-settings principle.
  - `kind` inference from names for the dialect providers: the IDs-only endpoints report no kind, and the sheet's `chat` default misclassifies OpenAI's whisper, tts, embedding, image, and video models; a curated name-pattern table per file is the only signal available.
  - Every provider fact the UI needs comes from the sheet: `ProviderSlice` publishes `openai_base_url` and `env_vars` alongside its existing descriptor copies, so no UI module holds a provider table that could drift from the crate. A hand-maintained mirror was considered and rejected on the hoist-not-mirror principle.
  - The sheet publishes the OpenAI-compatible chat base, not the model-list base: the two differ for most providers (Anthropic lists at `https://api.anthropic.com` and chats at `https://api.anthropic.com/v1`; OpenRouter lists at `https://openrouter.ai` and chats at `https://openrouter.ai/api/v1`; Cohere's compatibility endpoint is `/compatibility/v1`; Gemini's is `/v1beta/openai`), so writing the list base into an `[[endpoint]]` would produce broken configs. Which URL a vendor's compatible API lives at is per-vendor knowledge, so it is declared in the provider file and published, and its absence (`None`) is what makes a provider not addable.
  - The gateway downloads and disk-caches the sheet, checking freshness once per launch against a one-week age: the operator's words - "the gateway needs to download and cache the json asset file. and on launch check it once per week to see if there's a newer one" (2026-09-14). The cache lives at `<profile>/cloud-provider-models.json`; the check is a launch-time timestamp comparison, not a timer loop.
  - The download never blocks startup: boot loads the cache from disk, and any download runs as a background task spawned after the async boot completes. No event-loop or startup-robustness changes are needed - the gateway already runs background supervisors (llama-server, STT boot) on the same tokio runtime, and this is one bounded request with failure contained to the feature. This answers the operator's question - "do we need to make the gateway's event loop more robust?" - with no.
  - The cache write is temp-file-plus-rename: a crash mid-write must never leave a truncated sheet that the next launch would serve.
  - The gateway downloads and caches the sheet and serves it to the config UI, rather than the SPA fetching GitHub directly: the admin surface is already loopback-walled with bearer auth, the gateway owns the bounded-client factory, and a server-side cache avoids every UI session re-downloading a 1 MB-class document.
  - The sheet URL is a constant default plus a `PROMPTFORGE_MODELS_SHEET_URL` env override, not a new `gateway.toml` field: no config-schema change for a value that should never differ in production.
  - The sheet reaches views through a subscribable client-side store, mirroring `ConfigStore`: both the Cloud tab and the Secrets tab depend on the sheet, and the first launch has none until the background download completes, so a view open at that moment must learn of the arrival rather than requiring the operator to navigate away and back. Short-interval polling of the gateway's loading answer is enough - the existing progress SSE stream reports command-queue work, and the sheet download is not a queued command.
  - The view is a three-level cascade - kind, provider, family - over one full-height table: the operator's design (2026-09-14), quoted in the Goals, implemented exactly as specified. Kind comes first because it is the question the operator actually has; the cascade makes the `kind` inference fix load-bearing.

'Claude Fable 5.1' not 'claude-fable-5-1', as long as we have the pretty name available" (2026-09-14). ### Step 6: Gateway sheet cache and admin route

- Component: gateway-sheet-cache

`crates/gateway/Cargo.toml` adds the `shared-gateway-api` and `shared-cloud-providers` workspace dependencies. New module `crates/gateway/src/cloud_models.rs`: in-memory `Option<Sheet>` plus a download-in-flight guard behind a lock; at launch, after async boot completes, loads `<profile>/cloud-provider-models.json` from disk when present and parseable (an unparseable cache is logged, treated as absent, and overwritten by the next successful download); spawns a background download only when the cache is missing, unparseable, or its `generated_at` is older than one week (launch-time timestamp comparison, no timer loop); fetches with `shared_cloud_providers::fetch_sheet` over a bounded client from the existing `gateway-protocol/src/http_util.rs` factory; on success writes to a temp file and renames over the cache (atomic replace) before swapping the in-memory copy. URL is a constant default (`https://github.com/cppalliance/promptforge-cloud-providers/releases/download/models/cloud-provider-models.json`) with a `PROMPTFORGE_MODELS_SHEET_URL` environment override; no config-schema change, no startup or event-loop changes. Route: `GET /admin/cloud-models` returns the in-memory sheet, a loading indication when no cache exists yet, or the download error; a refresh variant forces a background re-download regardless of age; registered beside the other admin routes in `crates/gateway/src/lib.rs` and loopback-walled the same way (lib.rs 539-561, 584-594). Tests: fresh cache does no download; week-old cache triggers exactly one; unparseable cache treated as absent; download failure keeps the old cache; concurrent route calls during a download never start a second one; the cache write is atomic; route tests against a loopback stub covering the sheet, loading, and error answers plus loopback-wall coverage. Deliverable: the route serving the real published sheet from the disk cache (manual check that a fresh gateway downloads the republished release and serves it).

</step-6>

### Step 7: Cloud tab - store, cascade, view, and add-model flow

- Component: cloud-tab-ui

New `crates/gateway-config-ui/ui/src/services/sheet-store.ts`: a subscribable store mirroring the `ConfigStore` shape in `services/config-store.ts` (`subscribe`/`notify`; views subscribe on mount), requesting `GET /admin/cloud-models` on shell mount, polling at a short interval while the gateway answers loading until the sheet arrives or an error is reported, then notifying; a refresh action re-requests and notifies again; data calls added to `services/gateway-api.ts`. New pure cascade helper module deriving the cascade from the cached sheet with no extra round trips: providers grouped by tier in the order Prime, Subprime, Niche, Aggregator (alphabetical within each, empty groups omitted), providers with no models of the selected kind flagged greyed/disabled, distinct `family` values scoped to the selected kind and provider with the "All families" default, canonical rows (no `variant_of`) with their variant counts for the "+N snapshots" disclosures; `embedding` and `classifier` entries excluded. New pure add-model merge helper merging into the loaded config document: append `[[endpoint]]` when none matches the provider name (`id` = provider name, `protocol` = `openai`, `base_url` = the slice's `openai_base_url`, `api_key` = `"${KEY_ENV}"` from the slice's key-role variable, omitted when `env_vars` is empty), reusing the existing endpoint when present; then append `[[model]]` (`name`, `upstream` = entry `id`, `endpoints = [provider]`, `kind`, `context`, `description`, `thinking`, and the flattened capability fields mirroring the sheet's field names); reject the merge when the sheet entry lacks `context_window` and the operator has not supplied one (the `ModelConfig.context` nullability gap). New `crates/gateway-config-ui/ui/src/views/cloud-models-view.ts` following the existing view conventions, laid out top to bottom: the kind lozenges as an exclusive radio group (chat, image, video, STT, TTS mapping to `ModelKind` chat/image/video/transcription/speech, default chat); a native `<select>` for the provider with one `<optgroup>` per non-empty tier and `disabled` on greyed providers; a native `<select>` for the family with "All families" first; the full-height table (the page, not the table, scrolls) of canonical rows with columns for name, context window, max output, compact capabilities (tools, images, thinking), pricing when present, and the add action; each row with variants gets a "+N snapshots" disclosure expanding variant rows beneath it; loading, loaded (showing `generated_at`), and unreachable (error with retry) states driven by the sheet store subscription so a view open when the sheet lands re-renders in place. The confirm-details dialog in the view pre-fills from the sheet entry, `name` defaults to `display_name` and stays editable, requires operator input for `context` when the sheet lacks `context_window` (IDs-only providers), and shows `description`; a variant row is addable (a pinned snapshot is a deliberate choice); submit sends the merged document through `PUT /admin/config` and the existing apply flow; shadow-save validation errors surface in the dialog verbatim; a failed apply reverts per the existing revert path; rows for providers without an `openai_base_url` (Bedrock, Foundry, Azure Speech, ElevenLabs, Deepgram, Soniox, Leonardo) render the disabled add action with the one-line reason. Registration: "Cloud" joins `TABS` in `components/tab-bar.ts` between Remote and Profiles with a lucide `Cloud` icon, hash route `#/cloud` in `router.ts` (`ViewId`), mount in `main.ts`. Tests: sheet store (`sheet-store.test.mjs` with a stubbed API, like `config-store.test.mjs`) polling until arrival and notifying once, error stopping polling and notifying, a subscribed view re-rendering; cascade helper (`*.test.mjs`) greying, empty tier groups omitted, families scoped to kind and provider, variant counts, and the display rule (`display_name` primary with `id` beneath when they differ, `id` alone when they match); merge helper thick unit tests (endpoint creation versus reuse, `${VAR}` indirection from the slice, keyless providers, missing-context rejection, capability field mapping); view-level tests for the dialog pre-fill, the required-context path, and the disabled rows.
