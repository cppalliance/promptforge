### Step 1: one route decision and a call-site enum

- In [crates/runvil-internal/engine/src/execute/scheduler/tool_call.rs](crates/runvil-internal/engine/src/execute/scheduler/tool_call.rs) (D1-9):
  - A private `ToolRoute { Builtin, Local, Catalog }` and a `tool_route(&self, id, alias) -> Result<ToolRoute>` that makes today's checks in today's order: a name in `RESERVED_TOOL_NAMES` is `Builtin`, a name the live frame's VM has as a local tool is `Local`, and anything else is `Catalog`. It borrows `&self` only, as `runs_alone` (lines 171-180) does today.
  - `prepare_tool_call` (lines 253-361) matches on `tool_route` first and hands its catalog arm to a new `prepare_catalog_call`. That function holds today's catalog work (binding, counts, the access fork, `ToolCaller`, `issue`) and returns the issued call, or an error.
  - `dispatch_tool_calls` (lines 129-166) asks `tool_route` per call, stops at the first call that is not `Catalog`, and calls `prepare_catalog_call` for the rest. `runs_alone` and the fallback arm that turns a non-`Issued` outcome into the internal error "a batched catalog call is issued as an effect" are deleted.
- A private call-site enum (D1-5), declared beside `ToolCallContinuation` in [crates/runvil-internal/engine/src/execute/scheduler/pending.rs](crates/runvil-internal/engine/src/execute/scheduler/pending.rs) (lines 59-74):

```rust
pub(super) enum CallSite {
    Script { turn: Option<u32> },
    Model { call_id: String, turn: Option<u32> },
    Batch { call_id: String, turn: u32, slot: usize },
}
```

  - `prepare_tool_call` and `prepare_catalog_call` take a `CallSite` in place of `call_id: Option<String>`, `turn: Option<u32>`, and `slot: Option<usize>`.
    - `dispatch_tool_call` (lines 94-105) builds `Model` from a request with a call id and `Script` from one without.
    - `dispatch_tool_calls` builds `Batch`.
    - Turn resolution keeps today's rule: the given turn, else the chain's counter. The parser accepts a script request that carries a turn (`crates/runvil-internal/lua/src/protocol/parse.rs` reads `call_id` and `turn` independently), so `Script` keeps that turn and behavior is unchanged.
  - `ToolCallContinuation` stores the `CallSite` in place of its `call_id` and `slot` fields. `apply.rs` matches on it: `Script` takes `accept_tool_call`'s script branch, `Model` and `Batch` its model branch (lines 168-208), and `Batch` sends the final answer to `fill_batch_slot` (lines 80-120).
  - `ToolCaller` (`crates/runvil-internal/types/src/tools/origin.rs` lines 21-30, public and `#[non_exhaustive]`) is unchanged. `Script` maps to `ToolCaller::Script`, and `Model` and `Batch` map to `ToolCaller::Model`.
- Unchanged: `dispatch.rs`, the Lua crate, the Harness, events, effects, turns, `public-api.txt`, and the four task built-ins.
