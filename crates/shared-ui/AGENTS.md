# shared-ui

Not a Rust crate: the shared TypeScript + CSS package both esbuild-built UIs (`crates/gateway-config-ui/ui` and `crates/workshop-server/ui`) consume. No build step, no dependencies, no `node_modules`; each UI references it as a `file:../../shared-ui` dependency and imports subpaths (`shared-ui/tokens.css`, `shared-ui/modal`, ...) as bare specifiers, which esbuild, `tsc`, and `node --test` all resolve through the package's `exports` map.

- Cursor Dark is the visual specification for both UIs, and `tokens.css` is its single source of truth. Copy exact values and structure from Cursor's installed source and `cursor-dark-color-theme.json`; never approximate from a screenshot or substitute a similar token. Preserve Cursor's original `color-mix()` formulas - never encode premultiplied RGB as straight-alpha hex. Tests that pin Cursor values point at this file.
- Layer position: `base`. A bare `shared-ui/...` import is a package import, so both UIs' `check-layers.mjs` walks exempt it by construction (they check relative specifiers only); treat it as a base-layer dependency like any other package. Nothing in this package may import from either UI.
- What belongs here: the token sheet and behavioral primitives both UIs converge on - the focus-trapped modal, the action-menu dropdown and `.menu` surface, the toast stack, the status bar shell (text + extras + the progress/indicators slot swap), the inline progress bar, and the button/input/select base classes.
- What does not belong here: anything product-specific. The gateway keeps its settings controls (slider, toggle, chip-input, settings-registry), the review-diff overlay, the key prompt, and the endpoint LED strip; the workshop keeps its agent chrome (prompt-input, tool-call-card, mode-chip, mention-chip), the Dockview integration, and the Shiki renderer. A primitive moves here only when both UIs consume it.
- Component CSS lives in the `components` cascade layer so a consuming UI's own rules always win over these defaults; `tokens.css` stays unlayered (custom properties only). Never add an outline, ring, or focus-like box-shadow: Cursor menus and controls define focus through state backgrounds, and each UI keeps its own focus convention.
- This package touches the DOM but stays app-agnostic: no services, no sockets, no fetch, no state beyond a component's own elements. Consumers own every lifecycle; components here own no timers or document listeners that outlive their element (the modal removes its keydown trap on dismiss; the toast's timers are `unref`'d).
- The murm-ui derivation notice for `dropdown.ts` / `dropdown.css` lives in `THIRD_PARTY_NOTICES.md`; keep the derivation comments in those files pointing at it.
