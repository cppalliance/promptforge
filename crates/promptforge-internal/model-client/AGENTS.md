# promptforge-model-client

This crate owns the model vocabulary: the chat-completions wire types, the neutral reply checks, and the model-binding vocabulary. It owns no transport and no wire parsing.

- No HTTP and no wire format. The crate never opens a connection, names an HTTP client, reads the environment, or parses a provider's wire body. The OpenAI wire code (the request body builder, the SSE reassembly, the body and metadata parse, and the HTTP failure classifier) lives in `harness-gateway-client`, which reaches this vocabulary through the `promptforge` facade; a change that needs it belongs there.
- The wire types (`Message`, `ToolSchema`, `ToolCall`, `Completion`, `CompletionResult`) are what a `Chat` effect sends and what its answer returns. They are `#[non_exhaustive]`; the constructors in `client/wire-canned.rs` are the one way to build them from outside, and they run the neutral reply checks in `normalize.rs` (nonblank call id and name, object arguments, distinct ids, a non-empty batch). A wire decoder builds every completion through them, so it reports those checks' kinds and messages verbatim; change a message only on purpose.
- `CompletionError` is the failure a round reports: a closed `CompletionErrorKind`, a message that is the kind's fixed phrase, and an opt-in `detail` holding bounded, escaped provider text. `MalformedResponse`, `EmptyReply`, and `Unavailable` may extend the phrase with `: ` and a specific the broker's own code wrote; provider text never goes in the message. A broker builds one with the constructors, and the Engine maps it verbatim. The crate has no catch-all error enum: a poisoned model-set lock is `ModelSetError`, which `ModelView` returns and the facade does not re-export.
- Metrics vocabulary is canonical in `promptforge-types`. This crate never defines a parallel metrics model. A `Completion` holds a round's metrics as one optional `CallMetrics`, and holds the `RawExchange` of request and response JSON only when a broker attaches it; the Engine reads that pair for debug capture and nothing else.
- The crate does not depend on a parser, Lua runtime, store, observer, or executor. Executors adapt to it. The one exception is the doctest-only `promptforge` dev-dependency the root `AGENTS.md` excepts: its doc examples alone compile against the facade, and no unit test, integration test, or bench imports it.
- No item is `#[doc(hidden)]` (the `build-xtask` ban rejects it). An operation on a facade-visible type that only the Engine performs is a free function in `detail`, which the facade never re-exports.
