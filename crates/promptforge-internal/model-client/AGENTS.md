# promptforge-model-client

This crate owns the model vocabulary: the chat-completions wire types, the SSE reassembly, and the model-binding vocabulary. It owns no transport.

- No HTTP. The crate never opens a connection, names an HTTP client, or reads the environment. `reqwest` and `url` are not dependencies; a change that needs them belongs in `harness-models`, which reaches this vocabulary through the `promptforge` facade.
- The wire types (`Message`, `ToolSchema`, `ToolCall`, `Completion`, `CompletionResult`) are what a `Chat` effect sends and what its answer returns. They are `#[non_exhaustive]`; the constructors in `client/wire-canned.rs` are the one way to build them from outside.
- The request body builder, the SSE reassembly (`SseScanner`, `StreamAccumulator`, `finish`), and the read loop over a transport's `ChunkSource` (`read_body_capped`, `read_completion_stream`) are shared by every transport, so one request shape leaves, one byte cap and sentinel rule bound every body, and one rule set judges every turn, streamed or buffered. The facade publishes the body builder, the read loop, `ChunkSource`, and `escape_controls` as its documented `transport` codec; the scanner and accumulator stay engine-internal. The strict turn rules stay in `normalize`; the accumulator only reassembles. A transport contributes only its chunks and its clock: this crate reads no clock, and the read loop measures `ClientTiming` against the `Instant`s the transport hands it.
- `CompletionError` is the failure a round reports. Its source type (`Error`, `Timeout`, published as `transport::ClientError` and `transport::ClientTimeout`) is documented transport API, so a transport can construct it and the engine maps it verbatim.
- Metrics vocabulary is canonical in `promptforge-types`. This crate parses responses into those types and never defines a parallel metrics model.
- The crate does not depend on a parser, Lua runtime, store, observer, or executor. Executors adapt to it. The one exception is the doctest-only `promptforge` dev-dependency the root `AGENTS.md` excepts: its doc examples alone compile against the facade, and no unit test, integration test, or bench imports it.
- No item is `#[doc(hidden)]` (the `build-xtask` ban rejects it). An operation on a host-visible type that only the engine performs is a free function in `detail`, which the facade never re-exports.
