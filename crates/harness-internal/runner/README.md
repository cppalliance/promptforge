# harness-runner

The per-run Harness and its effect loop. A `Harness` holds what the Host supplies (its recorder, its `InferenceBroker`, its timer, its capability registry, and its services) and drives one run as a single future: it resolves the launch model through the broker, prepares an Engine `Run` from the prompt's source (drawing the seed and start the Engine never draws itself, activating the prompt's capabilities, beginning the run at its recorder, and refusing an unsatisfiable prompt with the Engine's notice), steps it, performs each chat effect through the broker, each tool-call effect through the activated tools, and each timer effect through the timer, answers each Vfs effect inline, feeds the answers back, and reads the declared output file. Every performer future is polled inside the run's own future, so the Harness starts no task and any executor can drive a run; a `RunControl` stops the round in flight or cancels the run from outside. Private to the Harness family in `crates/harness-internal/`; clients reach it through the `harness` facade. Like every Harness crate, it may depend only on `promptforge` and its container siblings.
